# Gateway-microservice

[![Java Version](https://shields.io)](https://oracle.com)
[![Spring Boot](https://shields.io)](https://spring.io)

Центральный API Gateway (Шлюз) всей системы на базе **Spring Cloud Gateway**. Он является единственной внешней точкой входа для всех клиентских запросов (HTTP и WebSockets), отвечает за динамическую маршрутизацию, балансировку нагрузки и сквозную безопасность приложения.

## 🛠️ Стек технологий и особенности

* **Язык:** Java 17
* **Фреймворк:** Spring Boot 3.1.1 + Spring Cloud Gateway
* **Сборщик проекта:** Maven
* **Обнаружение сервисов:** Интегрирован клиент Сервера Эврики (Netflix Eureka Client) для автоматического поиска адресов запущенных микросервисов.
* **Балансировка нагрузки:** Использование Spring Cloud LoadBalancer для равномерного распределения трафика между инстансами.
* **Кросс-доменные запросы (CORS):** Глобально разрешены все методы, заголовки и источники со включенной поддержкой авторизационных данных (Credentials).

## 🔒 Безопасность и Аутентификация (AuthenticationFilter)

Шлюз защищает внутренний контур архитектуры с помощью встроенного кастомного фильтра аутентификации:
* **Поиск токена:** Фильтр автоматически извлекает JWT-токен либо из заголовка (`Authorization: Bearer`), либо из параметров запроса (`?token=`). Это обеспечивает бесшовное подключение для WebSockets, где стандартные HTTP-заголовки передать сложно.
* **Валидация:** Проверка подписи токена происходит на основе секретного ключа прямо на шлюзе. При неудачной проверке клиент получает ответ `401 Unauthorized`.
* **Обогащение запросов:** После успешной проверки шлюз извлекает из JWT данные пользователя и прокидывает их дальше во внутренние микросервисы в виде чистых заголовков `X-User-Id` и `X-User-Name`. Внутренним сервисам больше не нужно повторно парсить токен.

## 🔀 Карта маршрутизации трафика

Шлюз запущен на порту **5555** и перенаправляет запросы по следующим правилам:

1. **USERS-SERVICE (users-auth):**
    * **Тип:** Открытый маршрут (без фильтра проверки JWT).
    * **Назначение:** Точки регистрации, авторизации и базовых операций пользователей (`/login`, `/registration`, `/api/users/**`).

2. **RAGING-HORSE-TETRIS-4-1 (UI статика / tetris-ui):**
    * **Тип:** HTTP-маршрут (без фильтра проверки JWT).
    * **Назначение:** Раздача статического контента игры (HTML-страницы, скрипты, картинки, звуки, а также загрузка скриншотов и фото игроков).

3. **RAGING-HORSE-TETRIS-4-1 (WebSocket / tetris-ws):**
    * **Тип:** Защищенный WebSocket-маршрут (`lb:ws://` под управлением AuthenticationFilter).
    * **Назначение:** Активный игровой процесс, обработка сокетов и подключений SockJS (`/game/**`, `/websocket/**`).

4. **MONGO-SERVICE (mongo-service):**
    * **Тип:** Защищенный HTTP-маршрут (под управлением AuthenticationFilter).
    * **Назначение:** Запросы к сервису сохранения дампов игр и скриншотов (`/mongo-service/**`). Префикс пути автоматически отсекается (`StripPrefix=1`).

5. **GAME-SERVICE (pg-service):**
    * **Тип:** Защищенный HTTP-маршрут (под управлением AuthenticationFilter).
    * **Назначение:** Запросы к сервису статистики в базе данных PostgreSQL (`/game-service/**`). Префикс пути автоматически отсекается (`StripPrefix=1`).

## 🚀 Запуск и окружение

### Требования
* Установленный JDK 17
* Установленный Maven 3.8+
* Запущенный и активный `Eureka-microservice` на порту 1111

### Порядок запуска
1. Перейти в корневую папку проекта `Gateway-microservice`.
2. Выполнить сборку проекта и его запуск через стандартный плагин Maven для Spring Boot приложений.
